# kvm-k8s-lab — KVM + Kubernetes homelab as code

Full cluster lifecycle, "production-style", on home hardware:

- **Infrastructure as code** — Terraform + libvirt (3 VMs on a KVM host)
- **Cluster as code** — Ansible + kubeadm (idempotent playbook)
- **Platform as code** — ArgoCD GitOps (every app comes from Git)
- **Secrets as code** — SealedSecrets (encrypted secrets in Git)
- **Data protection** — Velero + MinIO (S3) + off-site copy on a Mac
- **Automatic backups** — in-cluster schedule + launchd agent on the Mac
- **Tested DR** — full cluster rebuild from scratch and restore

```
 │  qemu+ssh (192.168.31.110)
 ▼

 ├── k8s-control-plane  192.168.31.111   (40 GiB, 8 GiB RAM, 2 vCPU, host-passthrough)
 ├── k8s-worker01       192.168.31.112
 └── k8s-worker02       192.168.31.113

Cluster (Ubuntu 22.04, kubeadm 1.31, containerd, flannel):
 ├── Longhorn        — distributed storage (PVC)
 ├── MetalLB (L2)    — LoadBalancer for bare metal
 ├── ingress-nginx   — ingress + wildcard TLS
 ├── ArgoCD          — GitOps (App-of-Apps from gitops/root)
 ├── SealedSecrets   — secrets encrypted in Git
 ├── MinIO           — S3 storage for backups
 ├── Velero          — cluster backups + kopia fs-backup of volumes
 ├── Monitoring      — Prometheus / Grafana / Loki / Promtail, alerting as code
 └── Workloads       — task-api + PostgreSQL (Bitnami chart),
                       knowledge-graph-api + PostgreSQL (deployed by CI)

Automatic backups:
 ├── In the cluster: velero schedule every 6 hours
 └── On the Mac: launchd every 4 hours → checks the age of the last backup
```

## Quick start

### 1. Infrastructure

```bash
cd terraform
cp terraform.tfvars.example terraform.tfvars   # fill in libvirt_uri and key paths
terraform init && terraform apply -auto-approve
```

### 2. Cluster

```bash
ansible-playbook -i ansible/inventory.ini ansible/cluster.yml   # run from terraform/
ssh ubuntu@192.168.31.111 'sudo cat /etc/kubernetes/admin.conf' > ~/.kube/config
kubectl get nodes
```

### 3. Platform (GitOps)

```bash
cd .. && ./bootstrap/bootstrap.sh
```

### 4. ArgoCD credentials for the private repository (manual, NOT in Git!)

```bash
read -s GITHUB_PAT
kubectl apply -f - << SECRETEOF
apiVersion: v1
kind: Secret
metadata:
  name: kvm-k8s-lab-repo
  namespace: argocd
  labels:
    argocd.argoproj.io/secret-type: repository
type: Opaque
stringData:
  type: git
  url: https://github.com/sadqwes/kvm-k8s-lab.git
  username: sadqwes
  password: $GITHUB_PAT
SECRETEOF
```

### 5. Wait for sync and take the first backup

```bash
kubectl get applications -n argocd          # everything Synced/Healthy
velero backup create full-backup-1 --default-volumes-to-fs-backup --wait
# REQUIRED fs-backup check:
kubectl get podvolumebackups -n velero -l velero.io/backup-name=full-backup-1
```

### 6. Off-site copy on the Mac (outside the failure domain)

```bash
kubectl port-forward -n minio-system svc/minio 9000:9000 &
PASS=$(kubectl get secret minio-credentials -n minio-system -o jsonpath='{.data.rootPassword}' | base64 -d)
mc alias set local http://localhost:9000 admin "$PASS"
mc mirror --overwrite local/velero-backups/ ~/velero-backups/
kill %1
```

## Backups: how it works

The cluster doesn't run all the time (the host PC gets switched off), so one strategy is not enough. Three layers:

```
┌─────────────────────────────────────────────────────────────┐
│ Cluster (runs irregularly)                                  │
│                                                             │
│  velero schedule "0 */6 * * *"                              │
│  └── tries to back up every 6 hours                         │
│      (skipped while the cluster is off)                     │
└─────────────────────────────────────────────────────────────┘
                            │
                            ▼
┌─────────────────────────────────────────────────────────────┐
│ Mac (almost always on)                                      │
│                                                             │
│  launchd: every 4 hours → ~/velero-auto-backup.sh           │
│  └── Is the cluster reachable?                              │
│      └── How old is the last Completed backup?              │
│          └── Older than 24 hours → velero backup create     │
│              └── mc mirror --overwrite (whole bucket)       │
│                  └── ~/velero-backups/ (off-site copy)      │
└─────────────────────────────────────────────────────────────┘
```

### Auto-backup script (`~/velero-auto-backup.sh`)

```bash
#!/bin/bash
set -e

LOG_FILE="$HOME/velero-auto-backup.log"
exec >> "$LOG_FILE" 2>&1

echo "=== $(date) ==="

# Is the cluster reachable?
if ! kubectl cluster-info &>/dev/null; then
  echo "Cluster unreachable, skipping"
  exit 0
fi

# Age of the last Completed backup.
# NOTE: use kubectl — velero CLI -o json returns an array without .items
LAST_BACKUP_TS=$(kubectl get backups.velero.io -n velero -o json 2>/dev/null | \
  jq -r '[.items[] | select(.status.phase == "Completed")] |
         sort_by(.status.startTimestamp) | reverse |
         .[0].status.startTimestamp // empty')

if [ -z "$LAST_BACKUP_TS" ]; then
  echo "No completed backups yet, taking the first one"
  AGE_HOURS=9999
else
  LAST_SEC=$(date -j -f "%Y-%m-%dT%H:%M:%SZ" "$LAST_BACKUP_TS" "+%s" 2>/dev/null || echo "0")
  NOW_SEC=$(date "+%s")
  AGE_HOURS=$(( (NOW_SEC - LAST_SEC) / 3600 ))
  echo "Last backup: $LAST_BACKUP_TS ($AGE_HOURS h ago)"
fi

if [ "$AGE_HOURS" -lt 24 ]; then
  echo "Recent backup exists, skipping"
  exit 0
fi

BACKUP_NAME="auto-$(date +%Y%m%d-%H%M%S)"
echo "Creating backup $BACKUP_NAME..."

if velero backup create "$BACKUP_NAME" --default-volumes-to-fs-backup --wait; then
  echo "✅ Backup $BACKUP_NAME created, mirroring the WHOLE bucket to the Mac..."

  kubectl port-forward -n minio-system svc/minio 9000:9000 &
  PF_PID=$!
  sleep 3

  PASS=$(kubectl get secret minio-credentials -n minio-system -o jsonpath='{.data.rootPassword}' | base64 -d)
  mc alias set local http://localhost:9000 admin "$PASS" 2>/dev/null || true

  # NOTE: copy the WHOLE bucket (backups + kopia), --overwrite updates repository metadata
  mc mirror --overwrite local/velero-backups/ "$HOME/velero-backups/"

  kill $PF_PID 2>/dev/null || true
  echo "✅ Done"
else
  echo "❌ Backup failed"
  exit 1
fi
```

### Local copy: always the whole bucket

The `backups/<name>/` folder holds **metadata only**. Volume data lives in the shared kopia repository (prefix `kopia/`). So the off-site copy is a mirror of **the whole bucket** with `--overwrite`:

```bash
mc mirror --overwrite local/velero-backups/ ~/velero-backups/
```

Without `--overwrite` the mutable repository metadata (`kopia.repository`, `kopia.blobcfg`) is not updated, and new snapshots in the local copy are invisible.

```bash

```

## Disaster Recovery Runbook

Tested scenario: `terraform destroy` → VMs recreated → cluster from scratch → restore.

```bash
# 1. New VMs
cd terraform && terraform apply -auto-approve

# 2. Fresh SSH host keys (VMs were recreated — new fingerprints)
ssh-keygen -R 192.168.31.111; ssh-keygen -R 192.168.31.112; ssh-keygen -R 192.168.31.113

# 3. Cluster (from terraform/)
ansible-playbook -i ansible/inventory.ini ansible/cluster.yml
ssh ubuntu@192.168.31.111 'sudo cat /etc/kubernetes/admin.conf' > ~/.kube/config

# 4. Platform
cd .. && ./bootstrap/bootstrap.sh

# 5. ArgoCD repo credentials (see Quick start, step 4) → wait until apps are Synced

# 6. Bring backups from the Mac back into MinIO
kubectl port-forward -n minio-system svc/minio 9000:9000 &
PASS=$(kubectl get secret minio-credentials -n minio-system -o jsonpath='{.data.rootPassword}' | base64 -d)
mc alias set local http://localhost:9000 admin "$PASS"
mc mb --ignore-existing local/velero-backups
mc mirror --overwrite ~/velero-backups/ local/velero-backups/
kill %1

# 7. Restore
velero backup-location get    # wait for Available
velero restore create --from-backup full-backup-1 --wait

# 8. Resolve SealedSecrets ownership conflicts (restore brought back plain secrets without ownerReference)
for ns in default ingress-nginx longhorn-system monitoring argocd; do
  kubectl delete secret tls-wildcard -n $ns --ignore-not-found
done
kubectl delete secret task-api-postgres -n default --ignore-not-found
kubectl delete secret grafana-admin-password slack-webhook -n monitoring --ignore-not-found
kubectl delete pod -n kube-system -l name=sealed-secrets-controller

# 9. Verify
kubectl get applications -n argocd
kubectl get pods -A | grep -vE 'Running|Completed'
```

The old sealed-secrets private key comes back from the backup (secret `sealed-secrets-key*` in kube-system), so after step 8 every SealedSecret decrypts on its own.

## Known issues and fixes (learned the hard way)

| # | Symptom | Cause | Fix |
|---|---|---|---|
| 1 | `mc`: signature mismatch | password was rotated, the real one is in the secret | read it from `minio-credentials.rootPassword` |
| 2 | MinIO post-job: exit 127 / ImagePullBackOff | recent MinIO/mc images need x86-64-v2, VM CPU is qemu64 | pin an older image + `users: [] buckets: [] svcaccts: []` (otherwise the chart renders the post-job), or `cpu.mode = "host-passthrough"` |
| 3 | Velero BSL Unavailable, `no EC2 IMDS role found` | without an explicit credential the plugin falls back to EC2 metadata | `backupStorageLocation[].credential: {name, key}` in chart values |
| 4 | Secret from a SealedSecret recreated empty (DATA 0) | `credentials.useSecret: true` — Helm creates its own Secret on top | remove the block, reference the secret only via the BSL credential |
| 5 | `backups.longhorn.io not found` | kubectl picks the first CRD with the same kind | use full names: `backup.velero.io`, `backup.longhorn.io` |
| 6 | `REMOTE HOST IDENTIFICATION HAS CHANGED` | VMs recreated — new host keys | `ssh-keygen -R <ip>` |
| 7 | `Permission denied (publickey)` | VM user ≠ hypervisor user | `ubuntu` + key `id_terraform_libvirt` (source of truth: inventory.ini) |
| 8 | `git mv: not under version control` | tfvars/state are gitignored | tracked files — `git mv`, ignored ones — `mv` |
| 9 | ArgoCD: `Repository not found` after DR | repo credentials lived only in the old cluster | manual Secret labeled `argocd.argoproj.io/secret-type: repository` |
| 10 | ApplicationSet CRD: `annotations: Too long` | CRD > 256 KiB in last-applied | `kubectl apply --server-side` (already in install-argocd.sh) |
| 11 | SealedSecrets don't decrypt on a new cluster | the controller generated a new key | restore the old key from backup, or reseal with the new cert |
| 12 | `Resource already exists and is not managed by SealedSecret` | restore brought back plain secrets without ownerReference | delete the plain secrets — the controller recreates them |
| 13 | Postgres data not restored | ArgoCD created the PVC before restore; Velero skips existing PVCs | restore BEFORE GitOps sync / delete the PVC / targeted restore; for databases use pg_dump |
| 14 | `Multi-Attach error` on rollout restart | an RWO volume is still held by the old pod | `rollout undo` or delete the new pod |
| 15 | velero CLI: `no such host` in warnings/errors | the Mac can't resolve cluster DNS `*.svc` | debug via `kubectl exec` into the velero pod |
| 16 | Longhorn Setting stuck OutOfSync | the operator normalizes the value to `{"v1":"2","v2":"2"}` | write the value in live format, or use ignoreDifferences |
| 17 | FailedMount: secret not found on start | the pod started before the secret was unsealed | `rollout restart` once the secret exists |
| 18 | jq: `Cannot iterate over null` when parsing backups | `velero backup get -o json` returns an array without `.items` | use `kubectl get backups.velero.io -n velero -o json` |
| 19 | `mc mirror`: `Overwrite not allowed (mm-source-mtime)` | the local copy is newer than the source | harmless for kopia blobs, but `kopia.repository` and `kopia.blobcfg` must be updated — use `--overwrite` |
| 20 | MinIO 5Gi PVC hit 100% — Velero backups Failed, deletions stuck, ArgoCD OutOfSync after a live patch | `df -h /export` in the minio pod = 100%; `velero backup get` = Failed/Deleting; diff live 10Gi vs desired 5Gi | `mc rm --recursive` on the bucket → restart the minio pod (released file descriptors) → PVC 5Gi→10Gi + reconcile the manifest in gitops → recreate BackupRepository after the wipe → schedule TTL 720h→168h → Grafana alert `PVCFillingUp` (any PVC >80% for 5m → Slack) |

## Lessons

### Architecture

1. **Backups live outside the failure domain.** MinIO on the same disks as the cluster doesn't protect against losing the hardware; the copy on the Mac is mandatory.
2. **Local copy = the whole bucket, not the backup folder.** `backups/<name>/` holds only metadata; volume data is in the kopia repository.
3. **Order of operations matters.** Restore data before GitOps creates the PVCs.
4. **A DR runbook exists only once you've walked through it by hand.** Every row in the table above is a real fix, not theory.
5. **fs-backup doesn't guarantee a consistent database snapshot.** Check `podvolumebackups` after each backup; add application-level backups (pg_dump) for databases.

### For a cluster that isn't always on

6. **One backup strategy isn't enough.** An in-cluster schedule plus a launchd agent on the Mac that covers the gaps.
7. **The age of the last backup is the main trigger.** The agent looks at the date of the last Completed backup, not at uptime.
8. **`--overwrite` is mandatory.** The kopia repository has mutable metadata; without overwriting, new snapshots in the local copy are invisible.

### Operations

9. **Everything is public except the private key.** The kubeseal certificate goes into Git; PATs and tfvars never do.
10. **SealedSecrets key** — a rebuilt cluster generates a new one; the old one comes back via Velero restore.
11. **Repository credentials** — not in Git, created manually after bootstrap.
12. **Ownership conflicts** — after a restore, delete plain secrets that conflict with SealedSecrets.
13. **Startup race** — a pod can start before its SealedSecret is decrypted → restart the pod once the secret exists.
14. **RWO volume conflicts** — on rollout restart use `rollout undo`, or delete the old pod first.
